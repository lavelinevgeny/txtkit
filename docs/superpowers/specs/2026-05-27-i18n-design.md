# Internationalization (i18n) — Design Spec

## Overview

Add two-language support (Russian + English) to txtkit. Self-built i18n layer without external dependencies. Language auto-detected from browser, with a manual toggle. Technical terms (camelCase, Base64, JSON, etc.) stay in English.

## Decisions

| Decision | Choice |
|----------|--------|
| Languages | Russian (primary) + English |
| Approach | Self-built (no i18next/react-intl) |
| Initial language detection | `navigator.language` → `ru` if starts with "ru", else `en` |
| Language persistence | Zustand store + localStorage key `txtkit-locale` |
| Switcher placement | Next to "txtkit" header ("RU \| EN") |
| Technical terms | Not translated (camelCase, snake_case, Base64, etc.) |
| Transform result labels | Not translated (they are technical identifiers) |

## New Files

### `src/i18n/locales/ru.json` and `en.json`

Flat key-value dictionaries with dot-separated keys. Approx 80 keys each.

Key structure:
- `app.*` — app-level strings (title, error boundary)
- `smartInput.*` — input area strings
- `resultTile.*` — copy button states
- `resultTiles.*` — show all / collapse
- `catalogCard.*` — card labels
- `catalog.*` — full catalog strings
- `expanded.*` — expanded section labels
- `jsonTree.*` — JSON tree view strings
- `tools.<toolId>.description` — tool descriptions
- `tools.<toolId>.features.<featureId>.label` — feature labels
- `tools.<toolId>.features.<featureId>.description` — feature descriptions
- `json.*` — JSON structure report labels
- `detect.*` — detection labels
- `encode.*` — encoder error messages
- `jsonTools.*` — JSON tool error/success messages

Interpolation syntax: `{variableName}` in string values, replaced at runtime.

### `src/i18n/context.tsx`

React context providing `useTranslation()` hook:

```typescript
type Locale = 'ru' | 'en'
interface I18nContextValue {
  locale: Locale
  setLocale: (locale: Locale) => void
  t: (key: string, params?: Record<string, string | number>) => string
}
```

- `t()` looks up key in current locale's JSON, falls back to `en`, then falls back to raw key
- Interpolation: replaces `{name}` tokens with `params[name]`
- `I18nProvider` wraps the app, reads initial locale from Zustand store
- Locale state lives in Zustand store (persisted to localStorage)

### `src/i18n/plural.ts`

Russian pluralization utility:

```typescript
function pluralRu(n: number, forms: [string, string, string]): string
// pluralRu(1, ['слово', 'слова', 'слов'])   → 'слово'
// pluralRu(3, ['слово', 'слова', 'слов'])   → 'слова'
// pluralRu(7, ['слово', 'слова', 'слов'])   → 'слов'
```

Used in `detect.ts` for word count labels.

## Strings NOT Translated

These stay in English in both locales — they are technical identifiers:
- Format names: camelCase, PascalCase, snake_case, kebab-case, SCREAMING_SNAKE, dot.case, path/case, Train-Case
- Tool operation labels: Reverse, Trim, Capitalize, Slugify, Leet speak, Morse code, Binary, Base64 encode/decode, URL encode/decode, HTML escape/unescape
- JSON operation labels: Validate, Pretty print, Minify, Flatten, Unflatten, JSON → YAML, YAML → JSON, Structure, JSON escape, JSON unescape
- Detection type labels: Base64, URL-encoded, HTML entities, JSON, YAML, camelCase, PascalCase, snake_case, kebab-case
- Tool names: Case Converter, Text Stats, Text Transforms, Encoders, JSON Tools
- Stats labels: Characters, Words, No spaces, Lines, Sentences, Unique words, Bytes (UTF-8), Reading time
- Numeric suffixes: "B", "sec", "min"
- Icons and symbols

- Unit test for `pluralRu()`: edge cases (1, 2-4, 5-20, 21, 22, 25, etc.)
